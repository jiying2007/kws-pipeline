## Prepare reviewed metadata

After binding the actual independently reviewed report and verifier:

```sh
python3 -I -S -B research/english_v6_delivery/bind_b28.py manifest \
  --report "$B28_ENGINEERING_REVIEW/readback/completion.json" \
  --verifier "$B28_ENGINEERING_REVIEW/readback/readback.py" \
  --output "$B28_DELIVERY_SELECTION_REVIEW"
```

The new absolute output directory contains only the SHA-named manifest, exact
saved report and verifier bytes, a `selection_b28.json` proposal and the review
receipt. The actual checkout's selection remains unchanged. Once these reviewed
files and the real proof binding are committed, prepare the DATA entry:

```sh
python3 -I -S -B research/english_v6_delivery/bind_b28.py entry \
  --commit "$B28_REVIEWED_PIPELINE_COMMIT" \
  --output "$B28_DELIVERY_ENTRY_REVIEW"
```

This requires the entire tracked checkout to be clean and at the exact reviewed
commit. It captures 12 pipeline files by Git mode, blob SHA1, byte count and SHA256:
the original runner and byte transport, original loader C and CMake files, original
B0 packer, new B28 runner and contract, separate B28 selection and proof binding,
and the SHA-named manifest, complete report and verifier. The binder emits a review
draft; it does not change the DATA entry or activate a workflow.
