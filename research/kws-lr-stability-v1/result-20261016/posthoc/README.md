# 固定学习率稳定性实验：saved-logit 事后诊断

## 结论

在这个固定 seed、12 个已暴露正样本的单次轨迹中，501–600 步将学习率从 .003 降到 .0003 后，末段损失突增没有重现。原始固定 600 步终点仍是 greedy KW1 4/4、KW2 0/8、静音 prefix 全通过。以下 beam 结果是事后诊断，不更改该终点，也不选 checkpoint 或解码器。

| 固定观察点 | 原始 greedy KW1/KW2 | beam32 与 beam64 各自 KW1/KW2 | KW2 完整序列概率高于短序列 | 总目标损失 |
|---|---:|---:|---:|---:|
| 历史 A500 | 4/4；0/8 | 4/4；8/8 | 8/8 | .0111516481 |
| 历史 A600 | 1/4；0/8 | 2/4；0/8 | 0/8 | .1220694259 |
| 历史 B600 | 1/4；0/8 | 3/4；5/8 | 5/8 | .0199599862 |
| 新 A600 | 4/4；0/8 | 4/4；8/8 | 8/8 | .0106473481 |

B 的训练权重不同，其标量损失不能与 A 直接作为同一尺度排名。

新 A600 的 CTC=.00953393150，anchor=.00111341674。相比同轨迹 A500，总目标继续下降约 4.52%。新501更新前完整 payload（只排除 schema）与梯度范数也精确等于历史 A501；这项额外检查是事后核对，没有扩大原前500门控。

## 末100步稳定性

每步记录是更新前损失与裁剪前梯度范数；观察点是更新后。

- 历史 A：501–600 的损失范围 .007822156–.621408165，最大梯度范数 9.98614216，596 步触发阈值5的裁剪；597步损失增量 .592861146。
- 新 A：同一窗口损失范围 .010652380–.011151648，最大梯度范数 .0091979103，无裁剪触发；100个相邻差分均下降，最大的差分仍为 −.00000501703。
- 差分按更新 u=501…600 的 loss(u)−loss(u−1) 计算，包含500→501边界。历史 A 有7次正增量，新 A 为0。

降低学习率避免了本次轨迹的晚期破坏，保留并略提高了完整序列的概率；这不识别 Adam 内部失稳机制，也不是跨 seed 的因果效应估计。

## KW2 与解码

KW2 的完整目标是 [3,4,3,4]，比较短序列是 [3,4]。新600的8个样本，精确 CTC log(P完整/P短) 均为正，范围 .369171–.987320。它们的原始逐帧 greedy 仍输出短序列，但固定宽32/64的无语言模型 prefix beam 均恢复完整目标。

因此，新终点的 KW2 greedy 失败不能直接解释为“完整序列未获得较高概率”。有限 beam 的结果也不证明全局 MAP。beam 宽度、top1、观察点均沿用之前固定诊断，不搜索宽度、分数奖励或词典。

## 最小下一步建议（未执行）

优先分离解码问题，不追加训练。可先预先写死一个 saved-LP 的逐帧前缀触发审计：只用新 A600 的12条 LP，固定 beam32，与 raw greedy 并列；事先规定完整目标匹配、触发时刻、重复触发计数和不重置解码状态等规则，然后一次性遍历全部帧。这样能检验“句末能读出”是否同时意味着触发时间可解释，仍不能测负音频误激活。

此建议不授权新的实验。任何新增训练、真实音频前向、负例或未暴露组评估，都需要另定数据与预算并获得授权。没有导出权重，不能默认为现模型可继续调用。现有600/608预算全部用尽。

## 复现与证据绑定

三文件包：analyze.py、report.json、README.md。脚本仅用 Python 标准库，固定两份 accepted manifest SHA256，逐个验证1806个实际读取文件的 SHA256；report 保存脚本身份、manifest身份和全部输入哈希。DP、prefix beam 与四帧625路径穷举fixture沿用原独立审查过的方法。输出必须位于原证据目录之外，且以独占创建模式写入，不覆盖已有结果。

```sh
python -B -I analyze.py \
  --historical-result /path/grouped-balance-result \
  --new-result /path/lr-stability-result \
  --historical-manifest /path/grouped-balance-result-acceptance/hash-manifest.json \
  --new-manifest /path/lr-stability-result-acceptance/hash-manifest.json \
  --output /path/new-posthoc-report.json
```

未调用模型、optimizer、TTS或ASR。所有数据均为已暴露、机器标注的正例；不支持泛化、召回率、FA/h、流式延迟、部署成本或产品资格结论。只报告原固定600终点及清楚标识的事后诊断。
