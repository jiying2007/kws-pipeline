# A600 已保存 LP：逐帧前缀诊断

## 结论

现有输出足够分析“完整目标何时成为累积前缀的首选假设”，不够证明产品唤醒时机或重复唤醒率。只读取新 A600 的12条已暴露、机器标注训练正例，共1276帧；没有追加模型前向、训练、音频读取、TTS、ASR或远端写入。

- KW1：greedy 与固定 beam32 都为4/4；完整目标首次出现于第10–29帧，随后保持到片段末。
- KW2：greedy 8条全程未出现完整目标，片段末均为短序列 [3,4]。beam32 8条均出现完整目标 [3,4,3,4]，首次在第14–97帧，随后保持到末尾。
- 7条 KW2 的 beam 首选假设曾经等于短词；另1条由 [3] 转为 [3,4,3] 再成为完整目标。6条在相邻帧之间直接从短词切换到完整词。这是 beam 更换整条累积假设，不是该帧新观测到了两个已确认音节。
- 每条正确完整假设都只有一个连续区间，没有退出后重新进入；累积假设中完整目标最多出现一次。这只说明无重置诊断里未见重复假设，不能证明真实系统不会重复唤醒。
- 两种解码的逐帧累积假设均未恰好等于另一类别的完整唤醒词；这不等同于在独立混淆集上测得零混淆。
- 8条 KW2 的精确 CTC 完整/短词概率比首次大于1的帧，与 beam32 首次完整帧一致；之后一直大于1。片段末 log(P完整/P短) 为0.369171–0.987320。没有从这些数据选择阈值或解码器。

原固定600步终点仍是 greedy KW1 4/4、KW2 0/8；上述 beam 结果不替换终点，也不是独立效果评估。

## 为什么不能直接推导产品触发

核对了 [主线固定提交的 decoder.c](https://github.com/jiying2007/kws-pipeline/blob/e80527ad4b1d4cf299ab986441f3c3e60be32747/src/decoder.c#L393-L659)、[引擎事件与抑制路径](https://github.com/jiying2007/kws-pipeline/blob/e80527ad4b1d4cf299ab986441f3c3e60be32747/src/kws.c#L272-L346) 和相关测试。当前产品契约采用 max-path 关键词Trie，分离搜索保留惩罚和声学分数，以所选路径的token几何平均概率作为置信度；还有根词起始限制、非top1子路径惩罚、VAD、可选尾blank/前缀仲裁、命中后decoder重置与引擎抑制。[shipping配置](https://github.com/jiying2007/kws-pipeline/blob/e80527ad4b1d4cf299ab986441f3c3e60be32747/configs/shipping.xiaowo.json) 的阈值为.55、抑制间隔1200ms，并明确需要重新校准。

因此，不能把 beam 序列概率或精确 CTC 概率当作该 .55 置信度，也不能把无重置首选假设的一个区间当作一次产品事件。短词 [3,4] 是比较项，产品SKU明确不把“小窝”单独作为唤醒词。曾出现短词假设不等于产品触发了短词。

本次没有保存新研究模型所对应的运行时关键词包、实际VAD/配置/初始状态与事件记录，没有人工关键词起止边界、连续负例或设备日志；也没有可复用导出权重。现有LP支持此次前缀诊断，但不能单独复现该产品完整状态机与事件指标。训练预算600更新/608前向已关闭；保留的历史实验计划不得作为重启授权。

## 验证与复现

analyze.py 只依赖 Python 标准库。它验证8份输入的SHA256、accepted manifest身份及A600成员绑定、原计划/模型/前端/冻结队列链接、12条记录顺序与元数据、LP归一化、保存的raw greedy路径和末帧CTC损失。10份只读公开源码快照同时验证SHA256和精确Git blob SHA1。

数值自检穷举1–4帧、5类全部路径，4帧有625条路径；逐前缀对268个可达序列比较独立枚举概率、无剪枝beam概率与CTC动态规划概率，并检查重复token的blank隔离、区间、非重叠计数和非法输入。未执行产品runtime测试，保存的相关测试仅用于契约审查。

另一套独立概率域实现逐帧交叉校验12条1276帧的全部贪心、beam32、CTC概率、区间和重复计数一致，最大DP log误差1.07e-14、beam误差1.33e-15；另有588组穷举序列校验通过。原分析器第二次复现的报告逐字节相同。固定计划、原报告及8份输入哈希复核未变。
