Verification trust boundary: public-package verification without a trusted expected
admission authenticates internal structure and hash consistency only. It does not
prove a GitHub run exists or establish its source identity. The launcher always
supplies its source-validated admission; an offline reviewer must provide the
trusted --expected-admission file for that identity comparison. The result reports
identity_authenticated and verification_scope explicitly.

Observed platform/package metadata stays in local scientific/runtime identities;
public load records contain only their hashes, not raw runtime bodies or readable
version observations. Fixed model IDs/revisions are in the plan; admitted source
pins bind the immutable model/runtime locks and enforced runtime verifier. The
README's record-versions statement does not authorize exporting arbitrary receipts.
