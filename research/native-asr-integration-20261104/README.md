# Prospective native three-model orchestration

This directory contains an executable retained-boundary host, not a launched
campaign. There is no enabled workflow. The source lock binds the independently projected 64-input digest. Actual WAVs
and the input-lock body remain outside the public source publication. Sense
dependencies now include all eight reviewed identities, including the native
core library. Running still awaits the parent's persistence and source review.

The host uses the same reviewed setup/isolation/supervisor helpers, performs
primary and Whisper setup once, then three zero-forward model preparations.
Qwen preparation intercepts the unchanged scientific loader, observes its real
native resolver and stops before any inference. Sense does the same through its
reviewed frontend module; Whisper's retained loader already observes config.
The host assembles the policy from those actual prepared identity files and
validates it with the existing three-recognizer policy validator. No caller
`ready=true` can substitute for these files.

Inference reloads each actual model, re-observes its configuration, requires
exact identity equality with the frozen policy, then writes genuine strict
start/config/raw/completed evidence through NativeEvidenceSink. All original
sources, asset identities and native dependencies remain bound to exact bytes.
The parent must still review full integration and actual run evidence; mock
tests establish neither source authenticity nor successful inference.

Four batches of sixteen are planned. Each batch receives Qwen, Sense and Whisper
before the next batch begins. Thus the first sixteen form a useful early stage.
Failure or a missing slot stops the rest, retaining a fixed 192-slot denominator.
There are no retries, TTS calls or training runs. Per-call deadlines remain 300s;
setup <=1200s, stage <=1500s, shared inner deadline 4800s with 120s launch reserve
and 60s cleanup reservation. A future reviewed workflow must use one 90min job.

The previous four-input timings were setup 140s and Qwen 86s / Sense 26s / Whisper 17s.
Linear scaling of the 129s recognizer total gives 2064s plus 140s setup, about 2204s.
This is planning arithmetic, not a performance prediction: duration varies,
fresh batches reload models, and this design adds zero-forward preparation.
The 4800s bound may stop incomplete. It cannot promise 192 successful calls.

Native payload stays under the runner-private work directory. In-job admission
verification may read it. Only `aggregate-only/status.json` can be publicly
exported: fixed counts/status and no transcripts, raw native payload, source
audio, identifiers or arbitrary diagnostics. No public archive upload is wired.
Persistence after runner teardown is unresolved; no private destination has
been invented and the denied public raw-evidence upload is not retried.

Hard gates before any launch: approved private input/evidence delivery and
persistence; final model/source closure review; reviewed runtime-derived
Sense frontend resolver handling; full cross-worker source/phase equality;
parent-reviewed persistence/trust-root plan and explicit controlled execution.
Strict native records alone still do not create a reviewed train root.

## Independent no-audio preparation

`prepare_host.py` is an independent exact new-branch, run-1, attempt-1
campaign `research/native-prepare-20261104-v1`. It has a 1,800-second inner
absolute deadline, a 40-minute single-job outer timeout, two original locked
runtime setups and three sequential real model preparations. No audio directory,
blind job, identity map, or decoder input is mounted or manufactured. The new
candidate-zero preload retains the original asset, source, runtime and expected
tensor-schema checks; scientific model-loader bodies are unchanged.

After verified trusted imports and before any model constructor, the guard
refuses `torch.nn.Module._call_impl`, direct inference methods on existing Module
subclasses, and the reviewed families' public inference methods. This is precise
entrypoint observation, not a claim to intercept all functional Torch operators
or direct methods on future subclasses. The reviewed no-input loader path plus
zero observed guarded calls supports this specific preparation-only result.
Any attempted guarded call fails the campaign without retry. Guard restoration
is tested. Actual identities are validated together into a policy only after all
three preparations finish; preparation does not claim recognition or admission.

The full preparation bodies and policy remain runner-private and transient.
Only the three bounded status rows and config/source/asset/policy digests are
exported. No transcript, input, weights, native payload, raw logs, or original
source bodies are exported. Persistent evidence access remains unresolved for
full recognition. `host.run` therefore has an unconditional full-ASR launch
block until a separately reviewed change resolves persistence and trust roots.
The no-audio workflow does not relax that block. Source tests use invented
objects only and do not establish that the real preparations have succeeded.
