# Fixed shared backbone numerical parity

This is a separate, bounded numerical experiment for the two frozen speech
feature models. It compares the existing Python/ONNX Runtime reference with
native C and ARM C under QEMU on three fixed artificial PCM signals.

The profile is `FIXED_SHARED_BACKBONE_ONLY`. Its default command performs no
model inference. Actual execution requires a separately enabled, fully pinned,
first public-main Actions push in `jiying2007/kws-pipeline`. There is one
verification job and no automatic retry.

The classifier training experiment remains stopped at its independent evidence
gate: the actual terminal-source selection contains five Vosen train rows,
below the fixed minimum of eight. This numerical profile makes zero classifier
head evaluations, optimizer updates, TTS, ASR or phoneme-recognizer calls and
consumes no human or synthetic speech recordings. It does not change that data
gate, add examples or admit pronunciation labels.

## Fixed signals, sample clock and work budget

Each input is exactly 48,000 signed PCM16 samples at 16,000 Hz: three seconds.
The generated byte identities are fixed before any actual numerical result.

| Case | Construction | PCM16 little-endian SHA256 |
| --- | --- | --- |
| `zero` | All zeros | `55873fecc61a79e87ca550c7072e38ccdd7ecb600ace286fe4717952a97c42b0` |
| `sine400` | Fixed 40-integer cycle, 400 Hz, peak 8192, repeated 1200 times | `f81681f58003475f0e81e7625f1bf7d76fb018585d3757c0e3083af83c1a8b01` |
| `lcg14` | Starting at `0x12345678`, update `x=(1664525*x+1013904223) mod 2^32`; emit `(x >> 18)-8192` | `4e97af4846861db16ce7461517d405f60dca4473b515ae1efcb0f505221142dc` |

Each backend receives the repeating chunk pattern `[1, 1279, 257, 4096]`
samples, truncated only at the actual EOF. Its state resets between cases.
There is no EOF padding or invented final frame. The first embedding is
available at sample 16,000, followed by one every 1,280 observed samples,
through sample 48,000. That gives 26 embedding windows per case.

The fixed total is 78 embedding windows for each backend. The reference makes
78 mel-model calls and 78 embedding-model calls: **156 ONNX session runs**.
Native C and ARM/QEMU each have three replay processes, one per case. No
head model or head binary is loaded, linked or evaluated.

Every embedding clock has three trace stages:

| Stage | Values at each clock | Reference operation |
| --- | ---: | --- |
| Raw mel | 3,104 | `97 × 32` mel output from the trailing 16,000 PCM16-scale float32 samples |
| Normalized mel | 2,432 | Last `76 × 32` mel values, divided by 10 and increased by 2 |
| Embedding | 96 | Frozen shared embedding output |

The binary trace uses `EFFTR01\0`, then little-endian
`<IIQ` stage/count/absolute-sample headers and float32 values. Stage, count,
ordering and sample clock must agree exactly. Nonfinite values fail validation.

## Predeclared numerical comparison

Each finite element must satisfy:

```text
abs(candidate - reference) <= atol + rtol * abs(reference)
```

| Stage | Absolute tolerance | Relative tolerance |
| --- | ---: | ---: |
| Raw mel | 0.01 | 0.00002 |
| Normalized mel | 0.001 | 0.00002 |
| Embedding | 0.001 | 0.0002 |

These are the same three frontend limits declared before the full-head
verification results. They provide finite engineering bounds for float32
accumulation-order and layer-propagation differences on these fixed cases.
The absolute term covers near-zero reference values; dividing raw mel by ten
also divides its absolute tolerance by ten. The bounds are not a proof for
arbitrary speech or arbitrary parameters, and they must not be widened after
observing this run.

The reports retain the largest absolute error, the largest relative error for
nonzero reference values, the associated clock/component/value positions,
tolerance ratios, zero-reference mismatches and violation counts. Exact clock
validation is separate from numeric error limits. A failed stage remains a
failed experiment with its partial receipts; no model or signal is retried.

## Actual Actions command and retained output

The runtime is Python from Ubuntu 24.04 with `numpy==1.26.4`, `onnx==1.17.0`
and `onnxruntime==1.20.1`. Native GCC, the ARM hard-float cross compiler,
`libc6-dev-armhf-cross` and QEMU provide the two C replay environments.
Actual versions are saved. Real-model execution is limited to public Actions;
this command documents that job's wiring:

```sh
"$RUNNER_TEMP/backbone-venv/bin/python" -I -B \
  research/english_backbone_parity/backbone_parity_once.py --execute \
  --pins "$GITHUB_WORKSPACE/research/english_backbone_parity/backbone_parity_pins.json" \
  --pipeline-source "$GITHUB_WORKSPACE" \
  --frontend-source "$GITHUB_WORKSPACE/research/english_final_embedding_frontend" \
  --assets "$RUNNER_TEMP/backbone-assets" \
  --static-export-zip "$RUNNER_TEMP/backbone-parity-evidence/static-export.zip" \
  --output "$RUNNER_TEMP/backbone-parity-result"
```

The output directory must be new. Each compilation has a 180-second limit;
each C replay has a 300-second limit. The worker's total numerical deadline is
1,800 seconds. An outer 31-minute process limit, with 30 seconds for forced
termination, bounds the Actions command. The job limit is 60 minutes: its
individual steps total at most 57 minutes, including five minutes reserved for
the final `always()` artifact upload. This leaves setup and upload headroom
without increasing the worker's numerical budget.

The artifact `english-backbone-parity-<run_id>` retains the worker result folder
and workflow evidence folder. These include source/export bindings, build and
runtime metadata, per-case traces/comparisons, actual CPU and wall timing,
`RESULT.json` or `FAILURE.json`, the output manifest, raw original static-export
API records/ZIP, download-attempt receipts and command exit status. If a process
ends before its terminal receipt, the workflow records interruption as unknown;
it does not infer zero model calls. Partial files remain visible.

Native and QEMU CPU measurements describe this host experiment. They do not
measure an SSC305 audio chain, memory budget, stability or device latency.
Passing all three fixed cases would establish only the recorded backbone
numeric/clock comparisons for those cases. Classifier training, full-head
parity and KWS qualification still require their own actual evidence.
