# 唤醒词反复失败的框架、算法与测试审计（reviewing）

## 结论

已有冻结配对实验足以否定“只差一组参数”的解释。四音节 CTC 的训练损失和 token 准确率不能代表完整唤醒事件；整词单 token CTC 即使训练 loss 降至 0.011412，也在未训练声线双词 0/4，部分正例全帧 blank top-1。尾帧监督与空背景配对分别暴露了背景误触发和跨声线召回问题。当前各模型均为开发负结果，不能晋级软件候选。

Python/C 前端的既有三类合成波形逐帧测试通过：logmel 最大绝对差约 3.38e-6，PCEN-lite 约 2.15e-4；C 的五项单元测试也通过。这排除了这些固定输入上的公式级明显不一致，不能排除真实语音、分块、量化后事件翻转。现有 KWM provenance 记录矩阵量化 SNR，但没有逐帧浮点 PyTorch 与 int8 C 后验、词事件一致性验收；矩阵 SNR 不能代替模型行为测试。该项列为下一版模型结构开工前的硬门槛。

## 已确认的测试框架缺口及修复

1. `eval/run_corpus.py` 原先读取 WAV 并记录实测时长，却不核对参考 JSONL 的 `duration_s`。错误时长会进入事件范围、FAR/hour 分母与检测时间合法性判断。现已要求参考时长与实测 16 kHz PCM16 WAV 相差不超过一个采样点；不符直接失败。
2. `eval/score_events.py` 的诊断字段在无正例时给 FRR=0、无命中时给 p95=0。保持历史诊断输出格式，但只要调用相应门槛，缺正例/缺命中便失败；另加逐词最低正例数、纯负例累计时长、单条连续负例最低时长与纯负例 Poisson 95% FAR 上界的显式门槛。累计短片段时长不能证明连续流表现。
3. `training/iterate_domain.py` 的旧严格门槛仍以整个混合语料的 `far_per_hour` 作判断；其中正例录音时长会稀释 FAR，且旧接口不会自动要求新的覆盖门槛。正式配置和候选晋级在下一阶段须明确接线并设定来源独立、逐词样本数与连续录音的阈值；本次新增的是 fail-closed 能力和局部回归，不把旧候选重新判为合格。

## 算法与数据根因分层

| 层 | 证据 | 判断 |
| --- | --- | --- |
| 正例真值与域覆盖 | 未训练 Qwen3 声线可复核双词只有 4 条；Spark 固定 ASR 接受双词分别 2、4 条；同生成器声线和同 clean WAV 的场景派生并非独立说话人 | 样本太小，不能可靠估计泛化；错读/停顿需隔离，不能按输入文本贴标签 |
| 训练目标 | 音节/整词 CTC loss 低但 C 事件失败；整词原型出现全 blank 和早发事件 | 序列转写目标未提供可信的词结束事件时刻，需可靠结束边界与独立事件头；先固定边界证据再开发新 ABI |
| 负例与背景 | 171 条整词尾帧模型在两个 900 秒代理流有 292/324 次事件；加 100 条空背景后仍有 67/69 次，且召回 0/4 | 空白背景监督确有缺口，但单独扩背景无法兼顾召回和拒绝 |
| 近音与测试 | HI-MIA “你好亚”被 ASR 转为“你好呀”10/10；相同读音不同字的负例不能只用精确正字法拒绝；一些场景真值只是代理 | 负例要限定音节等价规则或逐条审核；旧观察集只能回归，不能反复调参后再称封存测试 |
| 制品身份 | 训练容器内 `repository_sha=null`、工作树有未提交研究改动；v4 锁早于尾帧/空背景实验及本次修复 | 本地证据只能用于研究交接；须重新锁定当前源码和完整实验制品后才能复跑或送审 |

## 下一轮进入条件

先冻结两个来源、两词、跨声线的可靠正例及词结束边界；补独立新鲜检查组，保留现有组作已观察回归。新 ABI 的浮点与 C int8 逐帧后验、分块不变性、事件时间对齐、拒绝近音和长连续流要一起验证。软件门槛必须显式设置逐词最低分母、纯负例统计上界和连续录音长度；任何一项缺证据或失败，`software_candidate=false`。真人目标词、实际 AFE 与目标板继续独立验收。
