# Independent ARM dependency snapshot

This is a new observation, never retrospective certification of #616. Its
original ELF/sysroot status remains `MISSING_ORIGINAL_ELF_SYSROOT`.

The opt-in driver builds four full B shared libraries and four C++ link clients,
but never executes them. It recursively inspects ELF dependencies, interpreter,
GNU symbol versions and build IDs in a declared sysroot. It runs exactly one
public minimal C probe to observe FPSCR, rounding, exception flags, HWCAP,
glibc version and the probe's loaded objects. No model, audio, frontend replay,
or synthetic numerical suite is executed by this driver.

Predeclared limits: 300 seconds total wall/child CPU; 30 seconds per command;
1 GiB address space per child; 8 MiB aggregate command output; 16 MiB retained
directory (report at most 8 MiB). At most 64 dependency objects, no retries.
Only newly built public ELF and JSON are retained, never a copied sysroot.
Compiler, binutils, QEMU and library identities are hashed before/after use.

Resolution is intentionally restrictive: artifact directory followed by sysroot
lib, usr/lib, lib/arm-linux-gnueabihf and usr/lib/arm-linux-gnueabihf. Multiple
distinct resolutions, missing libraries, escaping symlinks, dependency cycles,
RPATH/RUNPATH, cache/hwcap overrides and changed identities fail closed. Repeated
nodes in an acyclic graph are recorded once. Symbol-version requirements must
be provided by the resolved dependency. Public paths use @artifact, @sysroot
and @tool labels. System libraries are identified, not redistributed.

Static closure is not proof of every possible dynamic load. The driver does
not execute B or its C++ clients; only the minimal probe's actual loaded set is
verified. Arbitrary dlopen/plugins and board state are outside this contract.
Compiler-reported library candidates must match the declared sysroot resolution;
this does not certify every compiler header, linker script or static link input.
FPSCR is an observation, not a full numerical correctness test. All old numerical
FAIL results, default-off options, production ABI and qualification limits stay.

Historical scope correction: recovered strict failures belong to the canonical
frontend and old-head network. B v6 was exported without numerical validation;
its inherited gate remains unclosed. This snapshot does not assert that a
B-specific elementwise strict run has been found or performed.

The report starts as INCOMPLETE before work and is replaced on success/failure.
CI uploads the retained directory with always(), including failed attempts.
Failure cannot be converted to PASS because a report or partial ELF exists.
If retaining generated bytes would exceed the limit, their identities are kept
and the bytes omitted with FAIL. An oversized report falls back to a small FAIL
receipt carrying its digest; that receipt explicitly does not claim completeness.
Cancellation before upload may still prevent delivery; GitHub logs then remain
the record, and no completeness claim is made.
