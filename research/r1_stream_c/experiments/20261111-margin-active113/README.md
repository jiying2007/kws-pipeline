# V3 后续迭代：margin MLP 与 ACTIVE113

本轮得到一个具有实测资源收益的紧凑研究候选 **ACTIVE113**：模型文件减少 **19.26%**；9 组主机 CPU 配对全部更快，逐对降幅的中位数为 **35.15%**；6 组配对的 PSS 中位数减少 **388 KiB**。130 条已知记录在 host 与 ARM QEMU 上的完整 F/E、逐帧类别和时钟均与原保存基线一致。

原 R1 默认模型继续保留。ACTIVE113 的六个数值分数携带实际 OTHER 类别 ID，独立于原 2,601 维 logits ABI。结果和公开源码身份见 [RESULTS.json](RESULTS.json)，接入与模型格式见 [SDK 说明](competitor-active-sdk-v1/publication/README.md) 和 [模型卡](competitor-active-sdk-v1/publication/MODEL_CARD.json)。

## 两条实际完成的模型路径

| 候选 | 实际改动 | 已知训练事件流 | 已暴露开发事件流 | 结论 |
|---|---|---:|---:|---|
| margin MLP | 140→64→1；类别均衡采样与决策边界损失联合改变；一次2,000更新 | 96/96 完全保留 | 33/34 完全保留；少1个K1事件 | 拒绝并保留失败记录 |
| ACTIVE113 | 仅按96条训练记录选择113个 OTHER 原输出行，保留五个精确行 | 96/96 完全保留 | 34/34 完全保留 | 进入紧凑模型后续研究 |

两个 MLP 版本的失败均保留，未在看到本次开发结果后重训。本次 margin 候选同时改变采样和损失，结果不能归因于某一个单独改动。所有标准化、类别采样和裁剪选择只使用已知训练记录；4 条 unknown 不参与训练或本轮候选回放。

ACTIVE113 的 OTHER 是选定原行的真实最大值，没有拟合替代分数。开发缓存中17帧的 OTHER 分数低于完整头，最大低估1.9912006539；这些帧没有改变最终 winner 或事件。开发集中 OTHER 真正获胜的181帧全部被覆盖。这些观察仍不能证明未见输入上的全类别竞争等价。

## 紧凑 C SDK 与实际回放

保留原前端、骨干、缓存更新、检测器和时钟规则；113个 OTHER 行保持原 par4 双精度运算顺序，五个精确行保持原标量运算顺序。仅计算保留行。最大值并列时使用较小的原类别 ID，实际 OTHER ID 原样进入检测器。

| 回放 | 独立输入数 | 每端帧数 | 每端完整词事件 | F/E、时钟、类别 ID |
|---|---:|---:|---:|---|
| host | 130 | 12,255 | 86 | 全部相同 |
| ARMv7 / QEMU | 同一130条 | 12,255 | 86 | 全部相同 |

host 的 hidden140、五个精确分数及选定 OTHER 分数分别与原 teacher 缓存和先前冻结预测逐位相同。ARM 与 host 的六分数最大绝对差为 **5.258016244624741e-13**，全部通过项目既有 logit 条件：`abs(ARM-HOST) <= 1e-8 + 1e-8*abs(HOST)`，且每个绝对差不超过 `1e-6`。这里仅比较六分数，不是完整2,601 logits 或 posterior 验证。hidden140 的跨架构最大差为 **1.918465386552271e-13**，仅记录诊断统计。

### 原严格失败与补充协议完整保留

最初协议要求 ARM 中间层与 x86 teacher 缓存逐位相同，在135次实际调用后停止；这次严格位级门槛仍为 **FAIL_UNCHANGED**。一条新采集的原模型 ARM 数值对照证明：在该案例中，原模型与候选的同 ARM hidden140／五个精确分数逐位相同，且复现了相同的跨架构微差。没有把差异归因于尚未单独隔离的某个数学库函数。

随后另行冻结补充协议，复用135份已有输出，只执行125条尚未运行的 ARM 记录，再进行18次 CPU 和12次内存调用。总调用账为 **135 + 1 + 125 + 18 + 12 = 291**。已有候选功能回放没有重试，模型、二进制、行选择、阈值和资源顺序均未改变。原失败终态与新协议的通过结果分别保存。

## 资源实测

两个模型均使用只读 mmap，使用同一8.32秒既有输入、相同主机编译器和单 CPU。CPU 采用9组交替顺序，内存采用6组交替顺序；只使用无采集代码的 plain probe。QEMU 和 capture 的计时均不用于性能结论。

| 指标 | 原完整 par4 头 | ACTIVE113 | 差异 |
|---|---:|---:|---:|
| 模型文件 | 1,960,140 B | 1,582,624 B | −377,516 B，−19.26% |
| CPU 秒／音频秒，中位数 | 0.021045392 | 0.013833457 | 两个中位数之比降低34.27% |
| PSS，中位数 | 2,495 KiB | 2,107 KiB | −388 KiB，−15.55% |
| Private_Dirty，中位数 | 448 KiB | 428 KiB | −20 KiB，−4.46% |

**9组逐对 CPU 降幅的中位数是35.15%，范围28.78%–40.76%，9/9组获益。** 这与表中“两个边际中位数之比”是不同统计量。内存来自当前进程在流式运行后、销毁前的 `/proc/self/smaps_rollup`，不使用继承的 peak RSS。

这些是当前 host、单条固定输入的配对研究观察。ARM QEMU 只承担功能比较；真实 SSC305 性能和 BSP 兼容性没有测量。现有 ARM 构建使用 Cortex-A32／NEON-VFPv4／hard-float，探针要求测试 sysroot 的 GLIBC_2.35，不能据此推断未知 BSP 可直接运行。
