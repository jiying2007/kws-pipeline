# R1 全类别 OTHER：INT16 预筛＋原 par4 精确回退

**研究候选，仅输出头原型，不默认启用。** 保留全部 2,596 个 OTHER 类别、完整原 INT8 权重、五个精确输出、骨干、前端、检测器和时钟，不改变已冻结 R1 或 ACTIVE113。

## 算法

1. 每帧以 140 维隐层最大绝对值选择对称 INT16 步长 Q=maxabs/32767；按 RNE 舍入到 ±32767。无法安全量化时完整原 par4 回退。
2. 全部 2,596 个 OTHER 行仍计算 INT16 × INT8 整数点积，按原比例和偏置重建近似得分。
3. 按实际隐层重构误差、原行 L1 权重和比例建立双侧数值界，额外加入 IEEE64 运算误差裕量及固定 1e-6 + 1e-8×|approx| 安全余量。
4. 取所有 OTHER 行近似得分区间的最大下界 L。仅当某行上界严格低于 L 时将其排除；其余行按原类别 ID 升序执行完全相同的双精度 par4，返回最终真实 OTHER 最大分数及原始类别 ID。异常浮点运算回退完整原头。

这里没有完整 2,601 维 logits 或概率接口，不能直接代替全部 CTC 后验。文件仍为原完整量化模型 1,960,140 bytes，无法继承 ACTIVE113 的 19.26% 文件节省；状态额外占有每行上界及权重绝对值和，CPU/PSS 实际收益尚未测量。

## 已执行原始 C 输出头验证与 CPU 配对

完整 2,596 行 OTHER 原权重，将提交的真实 C 源码（Git blob
`9e5e7c2f6ad4cad8dd34a9d977ae2ceabe514361`）分别用
GCC/Clang 编译，逐条输入已有的 130 条 hidden140 记录。
完整 C 最大 OTHER 分数逐位一致、原始 ID 一致，全部
**12,255／12,255**，每帧仅 1–2 行进入原 par4 精算，
未触发数值兜底全扫描。ARM GCC 13.3、Cortex-A32
`-O3` 构建在 QEMU 8.2.2 下重复同样 12,255 帧验证通过；

## 同输入三路 OTHER 输出头筛查（新增）

进一步复用每条已知记录中的两帧隐层、共 260 帧，固定
GCC／Clang `-O3`，在同一轮交替执行三种**仅 OTHER 行**的算子：
完整原 2,596 行、INT16 全类别保守预筛＋原 par4 回退、
以及 ACTIVE113 冻结选择的 113 个 OTHER 行。第三组使用相同原权重
直接计算选中的 113 行，属于 **ACTIVE113 头部代理**，不是完整
紧凑 SDK、模型加载或系统级 benchmark。

| host 编译器 | 完整 OTHER 头中位 | INT16 全类别中位 | 113 行代理中位 | INT16 / 113 行代理逐对倍数中位 |
|---|---:|---:|---:|---:|
| GCC `-O3` | 57.773 ms | 26.991 ms | 2.480 ms | **10.85× 更慢** |
| Clang `-O3` | 92.473 ms | 35.644 ms | 4.428 ms | **7.73× 更慢** |

两种编译器均为 **9／9 轮选中 113 行代理快于 INT16 全类别头**。
这证明 INT16 的完整竞争保留确实有相当 CPU 代价；
尽管它比原完整头更快，**不应以它替换当前轻量 ACTIVE113 候选**。
但 ACTIVE113 对未选 OTHER 类别的风险并未因此消失，完整竞争
INT16 仍可作为独立权衡的研究模式。此处不能推断真实音频
FAR／FRR、整个 KWS CPU、设备内存或 SSC305 加速。

详细可追溯结果见 [THREEWAY_OWNER_RESULTS.json](THREEWAY_OWNER_RESULTS.json)；

## 实现、测试、晋级

- i16_certified_head.h/.c：head-only 的完整 OTHER 精确最大值与原 ID API，无默认启用、网络、音频读取、堆分配或额外模型文件。
- test_i16_certified_head.c：自造 2,601 行完整模型，与独立原 par4 算法逐位比较最终结果；覆盖并列、重置等价的独立帧、极端幅值、随机输入、参数拒绝和浮点环境。
- 已有 R1 CPU 源码契约入口调用 GCC/Clang 人工数组测试，不修改冻结研究工作流。

进入下一门槛前须在 owner 已有 130 条 hidden140 文件上编译运行 C，严格比较每帧真实 OTHER 最大值和 ID，记录精算行数与异常全回退；再执行 host/ARM 单线程配对 CPU/PSS。独立自然负流 FAR、真人正例 FRR、目标 AFE 词尾延迟、实板 SSC305 CPU/内存/功耗和 BSP 兼容仍必须分别完成。上一轮全局时间上界低效方案已在 PR #790 关闭、未合入；失败证据继续保留。
