# Closed ASR18 campaign preparation

This is the actual offline preparation entrypoint for future campaigns. It creates
one fresh review bundle from one campaign identity and one reviewed policy. It
cannot grant execution, reopen a sealed campaign, start a model, dispatch a
workflow, create a claim, update a ref, or overwrite current source controls.
`index.json` has no active campaign. r1–r5 and the original v1 are sealed.

## Prepare and check

From the repository root, choose a new output directory outside the checkout:

```sh
python3 -I -S -B research/campaign-capsules-v1/prepare_campaign.py create \
  --campaign k1-punctuation6-asr18-r6 --output /tmp/k1-r6-closed-review
python3 -I -S -B research/campaign-capsules-v1/prepare_campaign.py check \
  --campaign k1-punctuation6-asr18-r6 --bundle /tmp/k1-r6-closed-review
```

`create` exclusively creates six files: `capsule.json`, four legacy-format
control projections, and a self-excluding `derived-manifest.json`. It refuses an
existing output directory. A partial write is retained for inspection; it is
never treated as a valid completed bundle. `check` is read-only, regenerates all
six expected byte strings from the capsule, and rejects missing, extra, changed,
aliased, oversized, or non-regular files. It also requires the caller's expected
campaign identity. The generated files are preparation artifacts; do not copy
them over historical source or regard the check result as runtime admission.

The capsule admits only `draft_closed`, with null source/claim/input authority.
There is no enabled variant of this schema. Every execution, claim, publication,
review, transfer-recovery and retry approval is false in the generated controls.
The claim-control SHA-256 is calculated from the exact generated bytes. Preparing
another campaign does not modify Python code, scientific source, a posterior
manifest, or the historical retention manifest.

## What is and is not migrated

The concrete reduction here is four hand-edited control documents plus their
cross-document claim digest becoming one campaign input and a deterministic
projection. A scientific policy is selected by version and exact catalog pin.
A prepared bundle can be checked for derived drift without rerunning inference,
rewriting a large closure, or trusting a supplied enabled/owner flag.

The old runtime and posterior have **not** been silently switched to this
preparation schema. Their exact revision-bound gates still reject a future r6
control as a current r5 identity, and still reject missing approvals, old claims,
foreign scopes, wrong budgets and retries. This preparation entrypoint is useful
now, but does not mean the complete 28-file activation/19-file closeout migration
has been performed. A complete replacement requires separately versioned runtime
consumers and externally reviewed execution authority.

The existing `prepare_prerequisite` already separates 47 scientific members from
four inference control/helper members. It also includes the original scientific
limits in its canonical projection. This new policy preserves that exact
projection and its digest:

`72f0c949ed4778f30b5e412eff257617739621b7873971f40dca82ef8c74d5c9`

The broader `prepare_freeze` inference/setup/host closure includes current
execution controls and remains revision-bound. The policy's separate 80-minute
execution envelope does not overwrite its 70-minute historical scientific
baseline. Neither hashes nor generated metadata establish new prepare evidence.

## Stable code and immutable policy data

- `campaign_capsule.py`: strict pure schemas, scientific-body comparison, closed
  draft validation, and deterministic control projection; no legacy imports
- `prepare_campaign.py`: actual create/check CLI, bounded no-follow local reads
  and exclusive writes only into a fresh output directory
- `index.json`: small reviewed policy catalog and sealed campaign identities;
  no active campaign and no execution authorization
- `policies/k1-asr18-scientific-v1.json`: the exact 47-member historical scientific
  projection plus the separately named execution envelope; original bodies are
  not copied
- `test_campaign_capsule.py`: real CLI, migration-equivalence and negative tests

A change in science requires a new immutable policy version and explicit reviewed
catalog update. Editing a budget and recomputing only a capsule hash cannot pass.
Changing authorization cannot change the scientific identity. The catalog and
all generated documents are metadata; they are not signatures or independent
proof of approval.

## Verification

```sh
python3 -I -S -B research/campaign-capsules-v1/test_campaign_capsule.py
python3 -I -S -B -O research/campaign-capsules-v1/test_campaign_capsule.py
python3 -I -S -B -OO research/campaign-capsules-v1/test_campaign_capsule.py
```

Each mode runs 32 tests. The suite measures the real 47 source bodies, compares the
original scientific digest, validates generated release shapes with the existing
validator, and verifies the existing execution gate remains closed. It covers
foreign identity, sealed r4/r5, old-claim injection, missing approvals, changed
budgets, boolean-as-integer values, unknown fields, altered derivations,
symlinks/hardlinks, and attempts to overwrite existing output.
