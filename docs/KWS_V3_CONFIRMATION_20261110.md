## 二、资源探针与离线 ARM 构建

[PR #779](https://github.com/jiying2007/kws-pipeline/pull/779) 修复 `target_resource_bench.c`：JSON 输出后检查 `fflush(stdout)` 和 `ferror(stdout)`；磁盘满或输出失败时返回非零。回归使用实际 C 入口、真实 stdio 和零模型 SDK stub，覆盖完整 JSON 与 `/dev/full` 写入失败。原实现可复现错误返回成功，修复后通过。测试集合数量同步从 2 更新为 3，未放宽成功或 no-skip 条件。

三套资源程序针对 Reference64、INT8 scalar、INT8 par4 分别构建。固定工具链与新目录重建得到逐字节一致产物；二进制分别为 33,280、33,288、33,288 字节。这些是探针程序大小，不是模型权重或运行内存。

构建目标为 Cortex-A32 / NEON-VFPv4 / hard-float，ELF32 小端 ARM EABI5；动态加载器为 `/lib/ld-linux-armhf.so.3`，最高必需符号版本为 **GLIBC_2.35**。必须核对真实 SSC305 固件；不同 libc 或更旧 rootfs 需要使用兼容工具链/sysroot 重建。

本次复用了三个已存在 Actions 工具链制品并保存完整离线输入，未重跑这些工作流；没有执行 ARM 探针、QEMU 或模型。完整构建身份、依赖、哈希与零执行范围见 [ARM_RESOURCE_BUILD_20261110.md](../research/r1_stream_c/deploy/archive-20261110/ARM_RESOURCE_BUILD_20261110.md)。
