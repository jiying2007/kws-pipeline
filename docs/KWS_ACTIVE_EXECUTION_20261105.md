## 唤醒体验与误触发的取舍

完整的“你好小窝”“小窝小窝”是两条目标；单独“小窝”继续作为 partial/negative。
完整目标中的口音、连读、轻声仍属于正常正样本。
近音挑战集报告每条音频的误触发情况，不把剪辑时长堆积成自然场景 FA/h。
系统选择在共同自然音频 FAR 预算下比较召回，并单列口音、远场、噪声和连读切片。
初始 1 FA/h 上界预算是研究操作点，后续调整必须在新的比较前声明。

近音误唤醒不要求归零，不要求每一个小切片的点估计都不回退。
口音保护使用足够样本、预先声明的非劣界限与不确定性；界限不能看完候选结果后再挑选。
相同实际读音不能仅因文字写法不同而在同一任务中同时标正和标负。
完整目标确实出现在自然负流时，应复核事件标注与研究任务定义，不能通过错误负标签迫使模型拒绝正常发音。

## 并行候选与公平比较

| 路线 | 首个可检查产物 | 比较要求 |
| --- | --- | --- |
| RNN64 | 在同一新数据上重新训练的对照 | 不沿用旧权重冒充同数据对照 |
| FSMN-CTC | 新训练收据、持续流检测结果 | 导出数值等价与效果分别报告 |
| C1 causal | 既有因果卷积的真实音频训练；再做 CTC/两关键词直分类头消融 | 两个头属于同一路线，增加新输出描述，不伪装原 5-token CTC |
| Zipformer KWS | sherpa-onnx 原生预训练推理与同音频评估 | 先测再决定是否微调；标明外部预训练数据差异 |

系统比较允许不同代码版本、模型标识、特征提取器和解码器。
共同约束是原始评估音频、事件标注、事件匹配协议、训练/开发/最终测试边界与选阈值预算。
单变量消融继续要求除所研究变量外保持一致，系统比较不能被表述成单变量因果结论。
不同历史 FAR 置信上界算法不能直接混合排名；新结果采用单侧 95% 精确 Poisson 上界。

## 环境、执行和恢复

活动宿主统一 CPython 3.12，由 `configs/runtime/research-runtime.json` 指定补丁版本。
core、tts、asr 是三个独立环境角色；仅在实际依赖冲突时隔离，不为 Python 3.8 继续维护一套活动入口。
运行时安装成功、import 成功、模型 forward 成功、真实音频训练成功分别记录，不能相互替代。

计算输出先保存，再发布证据。`dataset-driven-iteration.yml` 增加 `resume_artifact_run_id`：
在 main 发起工作流时指定先前运行 ID，即从该仓库同一工作流的 main dispatch 制品恢复，跳过编译、测量和重算比较。
后续系统横向比较通过 `baseline_artifact_run_id` 单独下载基线分数卡及输入包；不会让候选输出覆盖旧基线。
同一确定分支已存在时，先核对 scorecard 与 comparison 的完整字节，再补建/复用 PR。
PR 已关闭但未合并、或同一身份下出现不同结果时停止发布并留下证据，不覆盖历史。

活动计划要求模型任务按前置结果完成推进，定时 watchdog 只修复失联和停滞；控制器尚未部署时不能声称这条执行链已经自动运行。
当前重型模型进程并发为 1；先记录峰值内存，再按总资源提高并发。算法代码研发仍可并行。
每个研究项仍最多 999 runner-minutes；并发任务的实际 runner-minutes 累加记录。
新阶段最多两次基础设施尝试；确定性数值失败、质量失败不会靠无限重试筛选幸运结果。
外部 Codex 共用配额及付费模型 API 继续禁止。

本地 [`research_queue.py`](LOCAL_RESEARCH_QUEUE.md) 已实现冻结任务、完成驱动、
共享重模型槽、实际耗时累计及崩溃后不盲重试；隔离 CLI、嵌套进程终止与恢复契约使用无模型命令验证。
既有 D0 训练和原生系统测量仍保留各自原始运行身份，不回填成队列调度结果。
远端 GitHub 每小时 watchdog **尚未部署**，本地进程和机器也不是由这段源码自动托管。
外部槽忙、机器失联或未决任务仍需检查持久回执并再次调用本地入口；不能把这个缺口描述成已经自动恢复。

## 本轮验收如何表述

代码合并、CPU 单元测试、模型真实训练、自然长流 FAR、独立口音人声效果和目标板表现是分别可查的结果。

post-AFE 时差不能冒充原始采集时差；采样坐标时差不能冒充应用 callback 的实测时延。
