更新：2026-09-30。审查源码：`57d27efe1d584af45d5b1c086d02443c359b0e1b`。
本文是 [`KWS_LANDING_EXECUTION.md`](KWS_LANDING_EXECUTION.md) 的研究、数据和市场对标扩展，

目标是让 `你好小窝`、`小窝小窝` 在真实产品声学链路与目标硬件上可复核地工作，
再检验相对市场方案的优势；不是把一次训练、孤立片段准确率或合成资格变绿。

**优先顺序：输入与评估核验 → 轻量候选及外部参考的软件实验 →
按证据选择数据、目标与架构 → 最终 AFE/真实连续流、目标板与产品放行。**

不以真人录音或实体板到位为前提。合法数据、正确性测试、固定实验身份和停止条件仍需满足。
目标硬件按用户明确要求为 **SSC305 双核 Cortex-A32**；CPU 预算按**单核**归一化，并记录实际线程数，
不能因为双核就把单线程消耗除以二。资源优先看 **CPU 与 I/O**；模型可以更大、RAM 可以更高，
不能以最小参数量或旧 RAM 估算替代质量目标。当前以合成数据或获权现成开源数据推进完整软件交付、
ARM32 实现与集成包，板端主要承担后续验收测试，不作为前期开发或架构研究入口。
真实人声、最终 AFE 和 SSC305/DUT 证据仍是产品资格条件；同预算市场优势须另行证明。
Qwen TTS 应成为优先验证的数据来源候选，但“听起来更自然”不等于更低的真实 FRR/FAR。

该分支新增 [Qwen/真实语料扩展研究](https://github.com/jiying2007/kws-pipeline/tree/c4025ee2e686c0c6cfd1ba078e6d1dabc3f70ee8/docs/research)

仅覆盖那 20 条，不能延伸为所有未来批次合格。

应迁移的是实验设计：预声明 spec、原始/PCM hash、已见数据退出留出角色、

未绑定源码模型、同源短片段上的“零 FA 即成功”结论。外部公开语料的 FA readback
可用于压力诊断，但语料关键词、语言、来源和时长必须单独解释，不能冒充本 SKU 正例或最终资格。

## 2. 全链路责任图与交付边界

| 层 | 首要问题 | 最小交付 | 阻断条件 |
| --- | --- | --- | --- |
| 产品定义 | 两词、距离、语言、使用状态和可接受错误是什么 | 冻结 SKU、场景矩阵、资源预算、事件定义 | 目标随结果移动 |
| 数据权利/采集 | 可训练、可商用、可留存、可重分发吗 | 来源/许可证/同意记录，私有采集计划 | 权利不明或未经同意的声音克隆 |
| 清洗与分割 | 标签、时长、近重复、人物/会话是否泄漏 | 字节绑定 manifest、split audit、污染报告 | 假时长、重复来源跨 split、错误文本 |
| TTS/声学渲染 | 新来源是否增加有效域覆盖 | 等预算来源消融、发音 QA、渲染参数 | 只凭自然度打分选训练源 |
| 特征/训练/量化 | 改善来自何处，能导出吗 | 固定预算配对实验、checkpoint/导出 provenance | 同时更改多个变量、只看 loss |
| C 解码/事件 | 前缀、VAD、状态、端点和 FA 如何形成 | 帧级诊断与连续真实 C detections | surrogate 改善但实际事件退化 |
| AFE/整机 | 双麦/结构/AEC/AGC/NS 如何改变分布 | 最终 AFE 身份、同步回放与真人开发报告 | 用代理 AFE 结论替代量产链路 |
| 市场对标 | 同音频、同预算是否真有优势 | 可合法运行的匹配任务对标与区间 | 竞品不支持同词、无法本地运行仍混排 |
| DUT/发布 | 实时、功耗、稳定与证据是否闭环 | Phase A/B/C 同一 tuple 证据 | 软件 CI 冒充板端或产品通过 |

## 3. 数据账本、分割与资格隔离

### 3.1 每个来源先建账，后导入

每个数据集、TTS 模型、噪声/RIR 包至少记录：来源 URL、获取日期、版本/commit、
文件和 PCM SHA-256、许可文件快照与 hash、商业训练/模型分发/原音频再分发限制、
归属声明、保留/撤回要求、采集或生成方法、质量与缺失字段。
代码、模型权重、训练语料、生成音频、声音/人格权是不同的权利层；
仓库的宽松代码许可证不自动覆盖模型或所有依赖数据。存在不明确条款时，
该来源保持 `research-only/pending-rights-review`，不进入产品训练或公开制品。

TTS 另记 provider/model revision、模型与 tokenizer hash、speaker/voice identity、
prompt/text/seed、采样参数、语言与发音控制、源采样率和真实频带。
真人另记伪名化 speaker/session/source/room/device ID、同意用途和采集链路；
真实姓名、联系方式和原始/AFE 后音频不进入公开 Git/CI 制品。

### 3.2 Split 以来源关系为单位，而不是 WAV 文件随机分

- 同一真人、会话、母录音及其裁剪、增强、混音后代不能跨训练与独立评估
- 同一克隆声源、参考音频、voice embedding 与其衍生 voice ID 作为一个身份组
- 同一个 TTS generator 的不同 voice slot 只能证明 voice-slot 泛化，不能证明真人或跨生成器泛化
- 建立单独的 leave-one-generator-out 开发挑战集；不把每个生成器全部混入训练后仍称跨生成器评估
- 背景/音乐/回放素材、RIR/房间和设备会话按母来源分组，防止只对文件名或随机种子隔离
- 检查文件 hash、PCM hash、近重复/音频指纹、转录与时间重叠；失败则修复分割后重做基线
- 保留 split-role 消费台账；查看失败并据此改模型/阈值的数据永久转为开发反馈
- 独立真人资格在候选/阈值/最终 AFE 冻结后由受控通道一次使用，遵守现有 no-retry 政策

可选择性借鉴分支 `tools/speech_like_corpus_plan.py` 的跨 provider 留出、
SHA 绑定人工/ASR/mixed receipt 和 manifest 合并；先做小 pilot，再决定是否需要完整移植。
ASR 只能辅助筛查，不能自行批准目标词与高风险近邻。

公共语料不自动干净：词标注与本 SKU 不符的录音需审查是否包含目标词，
开放语音录音也可能已经被预训练模型见过。无法证明去重时披露污染风险。
重复播放一小时素材 100 次可测状态稳定性，但不是 100 小时独立声学覆盖。

### 3.3 建立三个不同的数据产品

1. **开发最小集**：获权的新来源精确双词、近邻与长负流，支持低成本因果实验
2. **开发压力集**：真人多会话、3–5 m、后方、房间/硬件变化、播放/双讲/电机；可用于改进，不能兼作最终盲测
3. **封存资格集**：按现行 Phase A 策略独立采集，模型/词包/阈值冻结后测试；失败后不能就地调参再宣布 fresh pass

## 4. 优先实验队列与可证伪门槛

以下是**拟议研究门槛**，不能覆盖现有更严格的产品策略。
每轮先记录假设、主要指标、非劣界、计算预算、种子、停止条件、比较数和输出路径；
不在看完结果后修改判胜标准。开发筛选至少两个独立训练 seed，准备提升前再做第三 seed 确认。
先固定规模和算力做公平来源对照，再独立测量扩量收益，避免把数据来源与训练量混为一个变量。

| 优先级/实验 | 对照与假设 | 进入下一步的证据 | 停止/转向 |
| --- | --- | --- | --- |
| P0 评估可信性 | 用负例测试证明 WAV 实际时长、负样本暴露、逐词/逐切片覆盖可核对 | 虚增时长、缺远场正例、无负流、矛盾计数均 fail closed；正例原有 fixture 不回退 | 门禁未合并验证前不发布新质量结论 |
| P0 冻结基线 | 在同一真实 C runner/词包/前后容差下重算已知两模型 | 能复现计数与原始 detections、清楚分离 unknown/not-run/fail | 无字节或源码身份则仅历史参考 |
| P1 新数据源 | 旧 TTS、Qwen、另一获权生成器和获权真实声学表征分别对照；固定文本/数量/预算 | 先检查可用开发集的逐词与近邻行为；真人迁移在独立数据到位后另证 | 仅同生成器 test 改善或仅自然度提高则不扩量 |
| P1 负流与近邻 | train-only 加真实/合成近邻，固定正例量、目标、预算 | 固定校准规则下 FA 降低，逐词 FRR 的配对置信界满足预声明非劣界 | 静默换零 FA、词 2 改善换词 1 崩塌则停止 |
| P1 Qwen 质量桥接 | 比较文本准确性、缺音/重复/停顿/截断、频带与真实声学覆盖 | 盲审及辅助 ASR 发现的错误经过人工核对；C 事件和真人迁移改善 | ASR 分高但目标音素丢失/补全近邻则拒收 |
| P2 目标/解码对齐 | 单独验证 VAD 来源、CTC 区间、blank/前缀监督；保持数据与 runtime 不变 | 声学序列→C 路径→最终事件的改善可归因，并跨 seed/真人开发重现 | 再现历史低收益后重规划，不反复跑同一失败 |
| P2 AFE 域 | 同录音对比前/后 AFE，固定模型，测 AEC 残留、双讲、AGC/NS 模式 | 明确故障属于 AFE、标注、模型还是解码；最终 AFE 数据改善后重算 | 代理 AFE 胜利不能关闭最终 AFE 阻断 |
| P1 架构替换 | 可立即比较受控的小规模因果候选，重审前端、目标、encoder、解码与 ABI；真人/板卡不作软件研究前置条件 | 正确性与固定软件实验支持后，只移植一个可维护候选；CPU/I/O 主导，RAM/模型大小可放宽 | 不以训练记忆、最小参数量或已观察短片分数选产品；失败先定位，不扫无界网格 |
| P3 量化/性能 | 对比参考、导出权重、C kernel，基于板端 profile 优化热点 | 逐层数值与最终事件容差达标，真实 CPU/功耗下降 | 先改精度或复杂度再猜测收益不可接受 |
| P4 候选/对标 | 固定一套候选与比较协议进入封存真人及合法 SDK 评估 | 现有资格门槛满足，独立对标支持限定优势声明 | 已观察测试重新校准、身份漂移即重开资格 |

建议开发判胜预注册例子：在预先选定的 FAR 上限下，主要终点为逐词最差 FRR；
要求相对基线 FRR 改善的配对区间排除零，且 FA 率差上界不超过事先冻结的非劣界。
如果样本不足以支持区间，不宣布胜负，保留为探索结果并估算追加样本需求。
首轮低成本来源筛选可直接预注册研究默认值：训练 seeds 1337/2346，
主要指标为各词最差 FRR，FA 作为独立安全指标；每个 seed 的两项点估计均不差于
冻结基线且至少一项严格改善才进入扩量讨论。此小样本筛选不是统计胜利声明。
后续有足够数据时，拟议非劣界为 FRR +1 个百分点、FA +0.01/h；
若置信界无法判定则报告不确定，不通过改宽边界获得胜利。
这些是研究默认值，不变更产品门槛；实际付费预算、硬件采购及产品语义改变另行确认。

## 5. 连续流、近邻与统计设计

### 5.1 正确的分母和事件

- FA 按真正送入同一 C 引擎的连续时间计数；清晰分别报告全流时长、负例专用暴露与有正例流
- 负例专用 FAR 不得把正例录音全部时长默认为负例暴露；混合流需冻结可审计的排除窗口规则
- 词 1/词 2 的真实事件分别评分；同时保留跨词混淆、重复触发、漏触发、端点前触发
- 记录从词尾到检测的 latency，保留 signed offset 和早触发计数；不能把早触发都截为 0 后称低延迟
- 采用产品政策词首前 0 ms、词尾后 500 ms 匹配；另外报告严格完整词完成后的触发质量诊断
- 流式评估保持模型/VAD/decoder/冷却状态连续；只有真实开机、XRUN、路由变化等才按产品 API 重置
- 冷启动、词前讲话、长静音后、连续对话、相邻同词/异词、多次近邻、播放启停、跨块边界均需覆盖

近邻至少含首音节缺失、尾音节缺失、同音/近音替换、音序交换、共享前缀/后缀、
重复音节、跨词拼接、真实自然句中相似音串，以及不同说话人接续片段。
人工核验哪些是完整目标词、哪些是明确负例，避免通过矛盾标签“学习”不可区分任务。

### 5.2 置信区间决定测试规模

产品沿用单侧 95% Wilson FRR 上界、单侧精确 Poisson FAR 上界。
零 FA 时 Poisson 上界是 `-ln(0.05)/T ≈ 2.996/T` 次/小时（T 为真实小时）。
因此零 FA 也至少需要约 23.05 小时才能使上界 ≤0.13/h；
上界 ≤0.10/h 约需 29.96 小时；≤0.01/h 约需 299.6 小时。
24 小时零 FA 的上界约 0.125/h，**不证明 FAR=0**。

这些数字使用平稳 Poisson 假设；家庭/说话人/房间的聚集误触发可能违反独立性。
除策略规定的区间外，报告按 speaker/session/room 的聚类 bootstrap 敏感性分析。
总 FRR 不能掩盖单词、远场、后方、播放、双讲、电机切片；切片重叠时披露交集，
不能把同一事件重复当作新的独立样本。若声称多个切片同时优越，应预声明主要终点及多重比较处理。

小规模 4 或 8 次预期唤醒只能筛查灾难性失败。
“2/4 对 3/4”不是市场优势证据；即使 0/600 漏检仍应报告区间，
不能把 600 次同一人的重复发声当成 600 个独立说话人。
样本规划同时受事件量、说话人数、会话数、场景覆盖、效应量和错误率约束。

## 6. 真实声学与产品资格计划

### 6.1 Phase A：直接沿用现行最低要求

权威：[real-human-qualification.policy.json](../commercial/real-human-qualification.policy.json)。
当前最低为 40 名说话人、每人至少 2 会话、1200 次总唤醒、每词 600 次、24 小时负例。
当前门槛：总/逐词 FRR ≤5%；单侧上界分别 ≤6.5%/8%；FAR ≤0.10/h、
上界 ≤0.13/h；p95 词尾后延迟 ≤500 ms。本文不放松门槛。

每词关键正例覆盖：0.3–1 m 至少 100、>1–3 m 至少 150、>3–5 m 至少 150、
后方至少 100、播放至少 100、双讲至少 80、机器人运动至少 80。
对应切片 FRR 门槛依政策分别为近/中距 6%，远距/后方/播放/双讲/运动 8%。
负流至少覆盖 household 8 h、speech_confusion 4 h、playback 4 h、robot_motion 4 h，
并满足总 24 h；重叠标签和剩余暴露需明确，不能简单把重叠小时相加。

采集规划同时包含：安静/高混响房间、正面/侧面/后方，3/4/5 m，
低声/快语速/自然停顿与相关口音，电视/手机/设备自身 TTS 音乐，
AEC 开启/收敛与打断、远端播放与近端双讲，电机/风扇/泵/机身振动、移动与静止。
记录麦克风、结构、扬声器、采样链路、最终 AEC/AGC/NS/VAD 参数及处理时序；
若产品计划的状态不在最小政策切片中，单独加入开发和产品风险报告。

原始输入、AFE 后输出与时间戳在受控环境绑定并保存；公开仅放脱敏聚合、hash、覆盖和 attestation。
按[真人资格运行手册](REAL_HUMAN_QUALIFICATION.md)执行，而非用本文绕过 intake、seal 或 no-retry。

### 6.2 Phase B/C：目标 DUT 是不可替代的最后证据

权威：[target-qualification.policy.json](../commercial/target-qualification.policy.json)、
[TARGET_AND_SHIPPING_PROMOTION.md](TARGET_AND_SHIPPING_PROMOTION.md)。
同一 SKU/板 revision/deployment/Phase A/最终 AFE/资源预算，至少 3 台独立 DUT，
每台至少 24 h soak，至少一台 72 h。

- 每 hop p50/p95/p99/max、RTF、p99 deadline headroom；p99 必须低于 block deadline，RTF <1，headroom >1
- 真实完整进程 CPU、RSS、stack high-water、温度、平均功耗，均低于预先冻结 resource-budget.json 数值
- 零 XRUN、discontinuity、丢样、backpressure；同时测试主动注入异常时是否按 API 安全重置
- 绑定 SoC、编译器/flags、DVFS/governor、热策略、音频路由、后台负载、硬件 revision、模型/词包/runner
- 保留 runtime-soak.json、power.csv、audio-continuity.json 与受控采集 attestation
- 板端公开安全音频遵守既有 non-human-public-safe 策略；真人 Phase A 音频不得因此被公开或混入板端公开包

当前 tiny RNN 使用 int8 权重，但 hidden state、activation/accumulation 为浮点，不能声称全 int8。
现有前端及 ARM scalar/NEON 对齐不能替代训练浮点模型→导出→C 的逐帧行为验证。
CPU 与 I/O 是资源选择的主约束，模型体积和 RAM 是要测量的成本，不是锁死现有架构的理由。
启动分别报告模型/词包逻辑读入量、冷/热加载与初始化；稳态分别报告每 20 ms block 的
CPU 时间、RTF、p50/p95/p99/max、文件 I/O、分配与音频连续性，模型尽量一次加载常驻。
预加载/常驻的设计意图不保证零物理 I/O 或零缺页，仍需测量实际页错误与存储计数。
模型文件字节、权重张量、因果状态、arena/工作区与完整进程 RSS 分开；
Python/ONNX/PyTorch RSS 不能冒充未来 C 端缓存，x86 时间和 MAC 不能换算成 SSC305 实测。
SSC305 双核 Cortex-A32 的 CPU gate 采用单核口径 `process-cpu-one-core-v1`：进程全部线程 CPU-seconds / wall-second × 100，不除在线核数、不截断超过 100% 的多线程值；记录实测线程数和 block deadline。
CPU-seconds/audio-second 仍需真实音频采样计数及采样率证据；当前 soak 不具备音频计数接口，该比率与音频时长明确为 null，不拿墙钟秒或独立 board-bench 的输入音频时长补造；
软件阶段先验证目标 ARM32 构建、ABI、固定内存、流式黄金轨迹与集成行为，再由板端验收实际 CPU/I/O。
具体产品预算结合目标 AFE 和并发业务负载确认；本文不把 x86 测量或研究预算模板写成已生效目标板策略。
使用目标板 profile 定位 FFT/前端/激活/矩阵/decoder 热点，再优化并重跑声学/资源门禁。
Phase A 或 B 任一失败，或 tuple 漂移，均不能进入 Phase C 的显式 shipping approval。

## 7. 市场对标：先定义可比较，再检验是否领先

建立两张分开的报告：

1. **检测器公平比较**：同一获权输入 WAV/PCM、采样率、块尺寸、麦克风/最终 AFE、
   同样两词、事件定义、正负暴露与目标硬件资源预算。每家仅在同一开发校准集选阈值，测试前冻结
2. **端到端产品比较**：若某 SDK 必须绑定自有 AFE/专用硬件，只能单列整机系统结果；
   披露前端和算力差异，不能声称同前端或同预算算法胜利

竞品需具备合法 SDK 访问、许可允许的用途和发布比较结果权限；
先读当前条款并记录版本，不能绕过授权、逆向限制、密钥或付费流程。
没有支持同一中文两词、可冻结版本、可用目标平台和合规运行路径的产品，标记“不可直接比较”，
不以宣传数字、英语通用唤醒词、剪辑准确率与本产品连续 FAR 混排。

预声明主要比较：同 FAR（及置信上界）下 FRR，或同 FRR 下 FAR；
同时报告 FAR–FRR 曲线、逐词/逐场景、p50/p95/p99 端点延迟、CPU/RAM/功耗和总成本约束。
所有检测器跑同一封存音频；配对分析以 speaker/session 为聚类单位，负流按源会话区块比较。
不把各自最佳测试阈值挑出来排名，不在看到测试错误后为某一家增加调参预算。

“优于市场”至少须满足：明确被比较产品/版本/词组/硬件/场景、样本与误差区间、
足够检验力、无关键切片退化、资源预算达标且可重复。
只能写成“在协议 X、候选 Y 和场景 Z 上相对版本 A 的指标 B 改善”；
公开资料或一个 SDK 不支持“超越所有市场产品”。

## 8. 每轮证据包与停止规则

每个实验输出自包含目录，至少保留：

- spec 与预声明分析计划、source HEAD/dirty diff、依赖锁定/工具链和执行环境
- 数据/许可账本、split/污染 audit、真实帧数/时长、原始/PCM hash、生成器与采集身份
- 有效训练配置、训练 seed/预算/样本数、checkpoint 和导出模型/词包 hash
- 校准规则/完整曲线/冻结 operating point、C runner hash、原始 detections/引用/评分 provenance
- overall/per-keyword/per-slice FRR/FA/暴露/区间、近邻错误分类、端点分布、失败清单
- 不确定性、未运行项、负结果、决策（继续/停止/重新采集）和下一步唯一变量

已消费的保留集不得回收为 fresh qualification；正式 seed 不因开发结果好看就提前消耗。
同一失败类别最多两次定向验证仍无信息增量，沿用执行检查点的重规划规则。
低信噪比增大训练量、继续扫阈值、恢复历史已退役入口均不是默认重试方案。

关闭研究里程碑需要“可复核数据与实验结论”，关闭产品任务需要 A/B/C 真正通过。
产品放行仍缺独立真人/最终 AFE、物理 SSC305/DUT 与冻结资源预算等证据；
市场优势还缺合法且可比较的 SDK 协议。软件研究不等待这些产品条件，
按每次实验真正需要的数据、计算与授权推进，缺什么就只阻断对应步骤。

## 9. 当前研究顺序与停止条件

1. **保持可核验输入与评估**：主线已有实际 PCM 时长、负例暴露与近邻回读保护；
   所有场景的最低样本配额仍未补齐，远场空分母防护不等于完整覆盖政策。
   通过 kws-data 单一验证/导出入口消费固定 commit/catalog/content ID，保留人审与 ASR、原生开发角色；
   不在 pipeline 另建音频归档或审核真值权威，不造 token 对齐和词尾时间。
2. **数据、目标与结构并行重审**：替代结构现在可研究；首轮只保留有限候选和固定预算，
   先检验可学习性、因果性、reset/分块一致性，再用同一开发协议比较。
   现有四次轻量实验未过双词目标，下一步调查获权真实普通话声学预训练/轻量表征或新的固定目标消融；
   不把局部失败变成保留旧 RNN 的禁令，也不沿用失败配方反复扩量。
3. **按质量、CPU 与 I/O 选可维护方案**：允许更大模型/RAM；先区别完整训练框架开销与可部署状态，
   记录启动/稳态成本及实际执行路径；用合成/获权开源数据推进 ARM32 软件实现、数值/流式验证及集成包。
   只给证据支持的候选建立一个可维护的 ARM32 交付路径与明确的 C-facing 集成接口；
   严格纯 C11 还是包含 C++/运行时依赖，要在集成约束中显式选择，不能把 C API 包装称作纯 C 实现。
   不为无需求的通用能力、兼容层或长期并存产品路线增加成本。
4. **板端作为验收阶段**：软件交付后在 SSC305/DUT 检查 CPU/I/O、音频连续性、AFE 集成与 soak；
   开发不等待板端。产品放行与真实人声/远场声明仍按 Phase A/B/C、长连续负流、独立标注和合法比较证据判断，
   缺少真人证据限制相应声明，不阻断软件开发。已观察的 42 片永远只作开发/回归。

研究和真实录音/硬件准备可并行。需要新来源权利、大批量下载、付费算力或 SDK 时按具体范围申请，
不用缺少板卡来阻断纯软件实验。历史 synthetic-search pause 仍记录旧线结论；
本文没有修改该机器配置、正式模型或 shipping tuple。

FA 诊断已从基础设施阻断推进到相位对齐回读，详见
[#429 检查点](https://github.com/jiying2007/kws-pipeline/issues/429#issuecomment-5908611391)：
该 seed1103 事件在 12.005 s 冷启动片段重现，长历史不是此次事件的必要条件；
补入前 80 samples 与帧网格一起改变，不能宣称相位单独致因。问题仍未修复，门槛不放宽。

| [sherpa-onnx 官方 KWS 模型](https://k2-fsa.github.io/sherpa/onnx/kws/pretrained_models/index.html) 与[代码许可](https://github.com/k2-fsa/sherpa-onnx/blob/master/LICENSE) | Apache-2.0 代码，约 3M 级中文/双语 KWS、可配置词，适合快速研究比较 | 具体权重/字典/tokens 商业授权未确认；WenetSpeech 来源需审查。C API 不等于纯 C runtime，依赖、内存、chunk latency 均需测量 |
| [openWakeWord](https://github.com/dscripka/openWakeWord#license) | Apache-2.0 代码，embedding/synthetic-training 思路可作方法参考 | 自带权重 CC BY-NC-SA 4.0，官方说明目前英语支持；不是商业中文模型直接替代品 |

数据、目标和架构现在都可重新比较，不要求先取得真人或实体板。
研究以固定输入、有限候选、因果/流式正确性与 CPU/I/O 证据约束；
软件结果支持后再逐步取得独立真实分布和产品资格，不能以小样本过拟合替代这些证据。
如果项目要求严格纯 C 而非 C-facing ABI，要在候选筛选时记录；
不能选中 C++/ONNX 方案后才把包装层视为满足纯 C 要求。
[CMSIS-NN](https://github.com/ARM-software/CMSIS-NN)面向 Cortex-M，
不能因为 SSC305 使用 Arm 就默认适用。

### 10.4 超过最小资格的市场比较采样建议

若产品需要较强市场比较，可在最小 Phase A 之外拟议：60 名独立成人 ×2 词 ×3 距离
（1/3/5 m）×4 条件 ×3 次 = 4,320 次，结合多房间/会话/DUT、方位和口音平衡；
另有足量电机/移动专门切片，不能只用四个泛化环境取代现有政策要求。
300 小时独立来源负流是检验约 0.01/h 零观测 FAR 上界的量级估算，非自动启动的采集任务。
这两个规模均为**可选研究设计建议，未批准预算、未完成，也不取代现行门槛**。
可以先以小 pilot 估计错误率和场景变异，再依据预声明效应量规划实际样本；
不要为了漂亮规模牺牲来源独立性。

需在录音前决定“电视或设备 TTS 说出完整目标词是否应触发”：
若希望判定是否对设备说话，任务已超出单纯词汇 KWS，可能需要播放参考、说话人/方向或其他交互机制。
不能把声学上同样的完整词任意标负，同时以降低 FRR 为目标，掩盖产品语义冲突。
