# C1 fixed-checkpoint onset sensitivity

This diagnostic follows the eight known training examples already consumed by
the 2,000-step C1 tiny-fit run. That run reached 5/8 exact full transcripts;
its saved errors include early common-prefix emissions. This motivates a
paired onset experiment, without treating the observed correlation as a cause.

The new script reuses the original model, frontend, full-text CTC evaluator,
source/row verification and local queue. It adds no optimizer or model-selection
policy. The prior 400/2,000-step jobs and their numerical artifacts stay intact.

## Fixed design

| Condition | Input | New forwards |
| --- | --- | ---: |
| 0 ms | Exact saved `numeric/after` features/logits, authenticated and rescored | 0 |
| 200 ms | 3,200 PCM16 digital-zero samples followed by unchanged original PCM | 8 |
| 500 ms | 8,000 PCM16 digital-zero samples followed by unchanged original PCM | 8 |

Each model call starts the same C1 checkpoint with a fresh sequence state. The
script constructs one model, never an optimizer. Eight samples and all three
conditions are fixed before execution. The order follows the original eight
rows, then 0/200/500 ms within each row. There are no alternative offsets,
thresholds, retries, discarded samples, new ASR, or label modifications.

The original logmel frontend uses 400-sample complete windows and a 320-sample
hop at 16 kHz. The offsets therefore correspond to exactly 10/25 frame shifts.
PCM is padded before running that same frontend; features are not fabricated
by concatenating zero vectors. The original feature suffix must remain equal.
The frontend subtracts a mean across feature bins inside each individual frame;
it has no across-time or global CMVN. Each observation explicitly retains the
aligned original feature SHA-256, baseline feature SHA-256, bitwise-equality flag
and maximum absolute feature delta; each condition summarizes those comparisons.
Any nonzero original-region difference stops the condition before a new forward.
Because a window spans 25 ms, the last window starting in the added silence
crosses the original PCM onset: only 9/24 windows lie entirely in added zeros.
Reported window coordinates are not phoneme alignment or inferred speech onset.

Saved observations include full-text CTC NLL, greedy output and edit counts,
blank occupancy, every greedy emission's posterior and time window, and the
number of emissions whose entire input window lies in added silence. Logits
are also compared after undoing the known 10/25-frame shift. A separate tail
delta is reported after the architecture's 14-frame receptive history; this is
descriptive, with no acceptance threshold or automatic verdict.

## Budget and execution

The recipe is generated by `declare`, which imports no Torch and performs no
model calls. It authenticates the original output manifest and successful
queue result, existing independent saved-tensor audit, exact eight-row selection,
original preparation, checkpoint, vocabulary and every consumed source file.
The runtime remains the original pinned Python 3.12.16/core dependencies and
deterministic single-thread CPU contract.

Use the existing `tools/research_queue.py` with one job, five global runner
minutes and five job minutes. The command is:

```sh
python3.12 -I -B training/research_c1_onset_diagnostic.py run \
  --recipe '{recipe}' --output '{output_dir}' \
  --heavy-lock /absolute/original-asr-runtime/heavy-model.lock
```

`run` requires that queue's inherited heavy-model lease and recipe binding. It
also checks the lock equals the one used by the original C1 run. A 240-second
signal and monotonic worker deadline leaves time within the five-minute queue
cap for cleanup. Sixteen forward starts/completions are saved separately. The
original eight 0-ms tensors are copied byte-for-byte; sixteen new per-condition
feature/logit tensors, source bytes and the fixed checkpoint are retained.
Any failure keeps partial evidence; the queue never retries a consumed claim.

`audit --output ... --manifest-sha256 ... --receipt ...` replays all 24 retained
conditions and the 16-call ledger under the same lock, without constructing or
calling a model. Save the declaration before execution and the result plus audit
afterward using the existing checkpoint-saving mechanism. This script does not
claim that local files alone constitute a durable external save.

The focused tests use fictional PCM and files, never model construction or
real speech inference. They exercise hop/window boundaries, CTC duplicate-token
collapse, fixed budgets, byte/roster changes, and immutable baseline intent.

## Interpretation

An early prefix that stays close to the reset time after adding silence would
support a reset-related shortcut explanation. A prefix that follows the
unchanged signal would support a different explanation. Results may be mixed.
Report all conditions and their timing; neither outcome justifies trimming
onsets, changing transcript labels, changing weak-label weights, or choosing a
model. The dataset is the known training cohort and provides no independent
generalization or device-performance evidence.
