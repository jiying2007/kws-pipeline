# 真人声学来源与训练方案重规划（reviewing）

## 结论与证据边界

当前迟迟无法落地具有**方案级原因**，不能继续把同一 TTS 提供器的说话人或轮数增加当作主路径。原 128 条训练池扩到 176 条后，独立 TTS 声音 C1/C2 的唤醒命中从两组各 8/8 降到各 7/8，近邻误触发从 1 次降到 0 次；召回与误触发没有共同改善。见[扩充训练配对回读](EXPANDED_TRAIN_UNSEEN_VOICE_CONTROL_2026-09-27.md)。

这次另用 [OpenSLR SLR120 HI-MIA-CW](https://www.openslr.org/120/) 的真人室内近邻语音做开发诊断。官方标注是“Hi Mia”的 12 种混淆短语，**没有本产品的目标词正例**；原始语音及完整逐条检测只放在本地 `/tmp/kws-real-negative-intake-20260927/`。数据许可为 CC BY-SA 4.0，训练/再分发用途需权利与许可审查，当前只作本地负例诊断，不导入正式模型或 qualification。

## 对现方案的结构性判断

1. **声学分布与标签覆盖不足。** 现有外部基座是单一 TTS 声学来源；增添同源声音后独立 TTS 召回与真人近邻抗性均恶化。它可做工程回归，不能代表真人、多房间、设备麦克风和最终 AFE。公开近邻集只能补负例；目标词真人正例必须由有权使用的采集提供。
   - 2026-09-28 的[固定 ASR 交叉回读](SYNTHETIC_ASR_ACCEPTANCE_2026-09-28.md)又发现原 AISHELL3 训练池中“你好小窝”及停顿版共 16 条在两套识别器下均为 **0/16 精确转写**，而“小窝小窝”连续版在 Qwen3-ASR 下为 **8/8**。这是第一词源音频发音/域适配或监督标签不一致的强线索，不能继续把训练失败只当阈值和超参数问题；来源级实听反馈“基本没问题”仍不足以判定每一条的真实音素。重建研究训练池应先补第一词的可信来源，保持正负与词间平衡，然后才测试损失或解码器变更。
2. **训练监督与运行事件不一致。** 当前 TinyStreamingRNN 输出 `<blank>` 加四个目标 token，以 CTC、粗时间区间、序列 margin 等代理损失训练；正式结果由 C 端 VAD/前缀/模糊子节点/阈值/抑制状态共同产生。代理目标下降不保证 C 端完整词事件改善，已经由上述配对结果证实。需要把 C 端唤醒事件、完整词/缺词混淆作为模型选择的硬指标，研究直接事件后验或显式拒绝头，而不是继续单改阈值。
3. **负例的词汇表示过窄。** 四个目标 token 不能忠实转写普通中文。大量非目标语音被迫成为 blank 或有限近邻目标，易学出与真实说话人/语境不稳定的边界。扩词表、音节级声学模型或直接词级事件头都是**待验证假设**，不预设哪一个会胜出。
4. **当前资源搜索结论仍有效。** [容量实验门禁](../../configs/training/kws-v2-efficient-encoder-closure-v1.json) 已否定继续仅在合成域堆叠 GRU。这里重启的是**数据与目标函数共同设计评估**，不直接放开更大模型或产品部署。

## 可执行的下一轮判定

1. **先获得正例与负例同来源对照。** 由声学 owner 提供目标双词真人正例和缺首/缺尾/同音/背景真人负例的受控入口，明确授权、说话人、会话、麦克风、最终 AFE 身份。产品 policy 要求至少 40 人、每人 2 会话、两词共 1,200 次唤醒及 24 小时负例；采集若未满足，只能开发，不得消耗正式资格。
2. **冻结成对实验。** 当前 CTC/H64 为基线；候选一是同资源级别、直接对两词完整事件和背景建模的流式头（参考[流式端到端关键词检测](https://arxiv.org/abs/1812.02802)）；候选二是保留声学 token 但增加可学习拒绝/完整词判别。两候选先做可部署 C 原型、资源估计、Python/C 输出一致性；在同一训练来源与冻结说话人独立开发集上比较每词 FRR、误触发/小时、延时及资源。先前 CTC+VAD 方向已有[端到端 KWS/VAD 原始论文](https://arxiv.org/abs/1611.09405)，不能假设架构一换就解决数据问题。
3. **一次只更换一个主变量。** 数据来源扩展与事件头更换分阶段对照；不在同一新集上反复选模型再宣称独立验证。设原 C1/C2 和 SLR120 为已观察开发证据，另留新说话人/新房间/连续负例作盲测；所有模型用同一 C runner/包/阈值选择规则。候选必须同时改善两个词的召回与近邻/连续负例误唤醒，不接受全拒绝或单侧改善。
4. **产品门禁单独执行。** 只有开发集稳定改善后才训练候选并冻结模型、词包、源码、AFE、目标板 tuple，执行 `commercial/real-human-qualification.policy.json` 的 Phase A/B/C。未有最终 AFE/板和真人目标词时，`shipping_approved=false` 不得改变。
