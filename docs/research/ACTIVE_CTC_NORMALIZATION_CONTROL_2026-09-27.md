本记录只涉及冻结合成语音开发集。正式配置、关键词阈值、C 解码器和已发布模型均未修改，也未读取 qualification。训练源码基线为 `e61264b9e16f3d0d9c0b7e37ec8df1900a84b647` 上的未提交实验改动；模型文件只保留在本地 `/tmp`，不具备发布身份。

## 假设与控制

正式 `training/train_ctc.py` 将每条 CTC NLL 除以输入帧数。历史启动上下文实验采用按目标长度归一化，但同时改变了活动区间、前后上下文和 600 epoch 预算。为避免把组合处理误归因为单项，这次只把**非空转写**的 CTC 分母从输入帧数换成目标 token 数；空转写仍按输入帧数归一化。其余保持 seed 1337、128 条冻结 train 记录、32 特征/H64 RNN、36 epoch、batch 16、现有辅助目标、默认 0.55 阈值及同一 C runner。

冻结语音池 SHA-256 为 `20346a75b33086d8085ebee7e72eacf4baad55c453a241e4f6babd710e222ce5`。两组 train/calibration/test 语料身份相同，使用当前源码独立构建的 Release/strict `kws_wav`，按词首前 0 ms、词尾后 500 ms 重算 C 事件。

| 归一化 | train | calibration | test | 第 36 epoch 有序 token 准确率 |
| --- | ---: | ---: | ---: | ---: |
| 原按帧 | 2/32 命中、4 FA | 0/16、3 FA | 0/16、2 FA | 0.873 |
| 仅非空目标按 token | 0/32、0 FA | 0/16、0 FA | 0/16、0 FA | 0.467 |

按 token 归一化使第 1 epoch CTC 项从约 1.14 放大到 15.80，却未解决 C 可执行路径，36 epoch 后得到完全静默的模型。原按帧对照也远未达到产品门槛。这个负结果只否定**当前 36 epoch、当前辅助目标和原始冻结语音**下的单项替换；不能否定与活动区间、上下文和不同预算联合设计的研究方向。单独替换正式归一化不应进入默认训练配置，实验代码已撤回。

## 正式链的独立制品问题

在同一审查中确认：正式 `--warm-start` 原先只核对架构与词表，没有把上轮 checkpoint 文件及加载的浮点权重身份写入下一轮 checkpoint/provenance，也没有拒绝显式开发实验 checkpoint。这会使多轮候选的来源链难以回读。对应源码修复以源文件 SHA-256、浮点状态 SHA-256 和未恢复优化器状态形成绑定，禁止源文件被输出覆盖，并在导出时校验并保留绑定；该改动不改变训练损失或模型结构。
