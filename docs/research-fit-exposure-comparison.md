# 固定训练样本的曝光预算对照

既有 400 步诊断中，C1 在 8 条训练样本上只有 1 条完整匹配；RNN64 输出同一个单 token。它们的有限梯度和 loss 下降已经证明实际优化发生，但没有证明完整文本可学会。C1 的高 blank 帧比例也不能单独解释为全空输出：原结果实际没有空输出，其中一条重复关键词已经完整匹配。

下一项受控问题是：在保持同一小集、初态、词表、特征、损失和优化器的条件下，预先增加训练曝光能否改变最终的完整文本记忆结果。该问题不使用开发集选参，也不把机器弱标签当成人工金标。

## 执行与记录

继续使用 `training/research_d1_fit_diagnostic.py` 原有 `declare`、`run` 和 `audit`。新任务从原初始 checkpoint 开始，预声明 2,000 步、每步 4 条、570 秒 worker 上限和 10 分钟队列上限；原 400 步任务及其失败结论保持不变。没有恢复旧优化器、自动重试、早停筛选或新增随机种子。

原封口 preparation 的全部文件必须通过既有严格校验，执行其原 20 个源码文件。后续主线文件与历史 preparation 不一致时，在原执行 commit 的独立工作树加入原诊断文件，不能削弱 preparation 校验或修改历史源码哈希。恢复文件的路径可以改变，内容、初态和 row identity 不变。

运行前保存一次性执行意图、完整 recipe、初始化但未消费的队列、原 preparation 清单、固定 8 条来源及 row binding、22 个执行源码文件和 Python／包身份。若后续运行环境消失，只有意图而没有 claim／结果不能证明“从未执行”；该任务必须保持结果不明，不能因队列文件缺失而重新发放。

## 不新增前向的对照阅读器

`tools/research_fit_budget_compare.py` 接收两个已封口输出目录及各自独立 `audit` 的文件和 SHA-256。它校验每份审计回执对应的完整输出清单及所有文件哈希，再检查：

- 同一候选、原 preparation、固定 2601 词表、8 条完整训练行、置信权重和 row binding。
- 同一初始 checkpoint／浮点参数身份、可训练参数集合和诊断源码。
- 除预声明步数、曝光数量和相应抽样序列外，优化器、梯度裁剪、CTC normalizer 与 seed 全部相同。
- 较长任务的共同抽样前缀与较短任务相同；后续仍按原小集循环。
- 优化前的保存统计、特征／logits 数值文件完全相同。
- 实际消费账本的前 400 步逐字节相同，包括每次 loss、梯度范数、来源、完整目标及权重。

结构控制不一致直接拒绝。若结构相同而初始数值或实际消费前缀不同，保留两项观察，输出 `numeric-control-mismatch` 并以退出码 2 结束，不把结果差异单独归因于曝光预算。此前没有宣称恢复出的全部传递依赖环境与历史环境逐字节相同；真实数值前缀是额外的控制检查。

阅读器只认证已经完成的独立 tensor 审计回执；它不会把元数据比较冒称为又一次 tensor 审计。读取阶段没有模型构造、推理、优化或 ASR／TTS 调用。

```bash
python3 -I -S -B tools/research_fit_budget_compare.py \
  --short-output "$KWS_FIT400_OUTPUT" \
  --short-audit "$KWS_FIT400_AUDIT" \
  --short-audit-sha256 "$KWS_FIT400_AUDIT_SHA" \
  --long-output "$KWS_FIT2000_OUTPUT" \
  --long-audit "$KWS_FIT2000_AUDIT" \
  --long-audit-sha256 "$KWS_FIT2000_AUDIT_SHA" \
  --output "$KWS_FIT_EXPOSURE_COMPARISON"
```

所有结果只说明所声明机器弱标签训练小集的可学习性。完整匹配改善、高 blank 比例或低训练 NLL 均不提供自然人声泛化、两关键词 FAR／FRR、设备成本或独立有效性结论。

## 2026-11-06 实际结果

新的 C1 任务实际完成 2,000 步、8,000 次训练曝光、16 次前后训练小集诊断前向，队列用时 **120.582647180 秒**。8 条输入、6 个来源家族、32 个完整目标 token 与原 400 步完全相同。原 preparation 的 311 个文件、20 个执行源码和原诊断文件先通过哈希校验。未使用开发集，没有 ASR／TTS 调用或额外训练重试。

优化前的 `before.json` 与其中绑定的特征／logits 文件逐字节一致；新任务实际消费账本的前 400 步与旧任务也逐字节一致，SHA-256 均为 `3dcd5db8e6c1f1ea651098a3a5d8395144f6cc8961899636433fb03f477c24b4`。这提供了此次曝光预算对照的实际数值控制证据。

从保存的 logits 和原 PCM 继续读取、没有新增模型前向，可见后两条错误的“你／好／小”分别在前端第 1／2／3 帧出现，对应 20／40／60 毫秒的窗口起点。普通负例对应 PCM RMS 约为 `3.79e-5`、`1.87e-5`、`3.82e-5`；一条正确 K1 也在相同早期位置发出这三个字。该现象支持“模型利用序列重置附近的起始状态和很弱的输入形成固定前缀”这一待验证假设。它不是人工音素对齐，也不能证明因果关系。RMS 只作描述，不据此裁切轻声、增加声源门槛、重标文本或排除说话人。
